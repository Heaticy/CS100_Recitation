\section{为什么使用Linux？}

\begin{frame}
    \frametitle{当我们谈及Linux时，我们到底在说什么？}
    \begin{center}
        “我只想插一句话，你所说的Linux，实际上是指GNU/Linux。”\footnote{https://www.gnu.org/gnu/linux-and-gnu.html}
    \end{center}
\end{frame}

\begin{frame}
    \frametitle{Linux是内核，GNU是用户空间}
    Linux本身只是一个\textbf{操作系统内核}，它负责管理硬件、进程、内存与文件系统。但一个完整的操作系统，还需要一些常用的\textbf{用户空间程序}（例如\code{bash}和\code{gcc}），而这些由GNU计划提供。

    因此，严谨地说，我们平时所说的Linux系统，其实是\textbf{GNU/Linux}系统。
\end{frame}

\begin{frame}
    \frametitle{Linux的发行版}
    Linux有众多\textbf{发行版}（Distribution），常见的发行版有
    \begin{itemize}
        \item Debian系：Debian、Ubuntu，包管理器为\code{apt}。
        \item Centos系：Fedora、Centos、Redhat，包管理器为\code{yum}和\code{dnf}。
        \item Arch系：Arch Linux，包管理器为\code{pacman}。
    \end{itemize}
    不同发行版在包管理器、默认桌面、维护策略等有一些不同，但使用起来是差不多的。

    \textbf{本课程假定你使用Ubuntu系统}（推荐Ubuntu 24.04或Ubuntu 26.04）。
\end{frame}

\begin{frame}
    \frametitle{有些事情本不应如此繁琐}
    \begin{vspquote}{Windows是糟糕的}
        Windows预装在每一台笔记本上，我们中的大多数人都习惯了，但“习惯”并不等于“合理”。
        
        Windows上的许多操作之所以繁琐，只是因为我们习惯了它繁琐的样子。
    \end{vspquote}
    接下来，我们用几个具体的例子，对比同一件事在Windows和Linux上的做法
    \begin{enumerate}
        \item 软件安装
        \item 系统更新
        \item 命令格式
        \item 开发环境
    \end{enumerate}
\end{frame}

\begin{frame}
    \frametitle{软件安装}
    在Windows上安装一个软件，往往要经历这样一番折腾
    \begin{itemize}
        \item 打开浏览器和搜索引擎，在众多结果中辨认官网，避开各类欺诈网站。
        \item 安装程序在下载后需要手动运行，需要一路点击“下一步”。
        \item 安装路径很随意，有的默认装进\code{C:\\Program Files}，有的需装进\code{C:\\}下的独立目录。
        \item 许多“科普”还会告诉你软件不要装\code{C:\\}要装\code{D:\\}，最终散布在各个盘符，难以管理。
    \end{itemize}
\end{frame}

    这里\code{apt}是Ubuntu的\textbf{软件包管理器}，它有三个关键特征
    \begin{itemize}
        \item 软件包集中化管理：软件集中在官方的软件仓库，不必去浏览器搜索。
        \item 软件安装方式统一：软件统一用\code{apt install}安装，自动解析依赖。
        \item 软件安装路径固定：在Linux上，软件安装的路径是有一套严格规范的。例如，执行程序会安装到\code{/bin}，库文件会安装到\code{/lib}，配置文件会安装到\code{/etc}，无需也不能手动选择。
    \end{itemize}

\begin{frame}
    \frametitle{系统更新：Windows}
    Windows的系统更新，大概是它最令人头疼的设计之一
    \begin{itemize}
        \item 强制性：更新常常无法拒绝，说装就装。
        \item 需要重启：更新后必须重启，有时甚至反复重启。
        \item 不透明：你很难知道这次更新究竟改动了什么。
        \item 只管自己：更新只覆盖操作系统，浏览器、Office、各种应用仍需各自更新。
    \end{itemize}
\end{frame}

\end{frame}

\begin{frame}
    \frametitle{路径与命令：Windows}
    Windows在路径与命令的设计上自成一派，与几乎所有其他操作系统都不同
    \begin{itemize}
        \item 路径用反斜杠\code{\\}分隔，且从盘符\code{C:}、\code{D:}开始，没有统一的根目录。
        \item 反斜杠\code{\\}又是大多数编程语言中的转义符，于是路径常常要写成\code{C:\\Users\\liyuxuan}，别扭又容易出错。
        \item \code{cmd}与\code{Powershell}的命令名称和格式都与主流格格不入，选项写法也不统一。
        \item 不同盘符相互独立，“根”不止一个。
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{POSIX：类Unix系统的共同规范}
    这些差异并非偶然。类Unix系统共同遵循一套接口标准——\textbf{POSIX}（Portable Operating System Interface），它规定了命令、路径、进程、文件等应当如何工作。

    遵循POSIX的系统有
    \begin{itemize}
        \item Linux与各种发行版
        \item macOS（它本质上基于BSD，也是一种Unix系统）
        \item FreeBSD、OpenBSD等
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{Windows才是那个异类}
    Windows是主流操作系统中唯一与Unix没有继承关系、也不遵循POSIX的系统，它才是那个异类。因此在Linux上
    \begin{itemize}
        \item 有统一的\code{/}根目录，用\code{/}分隔路径。
        \item 有标准的\code{cd}、\code{ls}、\code{cp}等命令。
        \item \code{-}开头是短选项（\code{-l}），\code{--}开头是长选项（\code{--help}）。
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{开发环境：Windows}
    在Windows上编写C或Python，往往要先请出一个庞大的IDE
    \begin{itemize}
        \item 写C要安装体积巨大的Visual Studio，连同大量可能永远用不到的组件。
        \item 写Python常通过Anaconda，同样捆绑了海量的库和图形界面。
        \item 这些软件把“编译、运行”包装在层层按钮之后，容易让人困在表象，忽略背后真正发生了什么。
        \item 而当需要敲命令时，又要面对糟糕的\code{cmd}，甚至不知道命令该在哪里输入。
    \end{itemize}
\end{frame}

\subsection{Linux能做到什么？}

\begin{frame}
    \frametitle{Linux不只是命令行}
    Linux是一个成熟的桌面操作系统：它有完善的图形界面，日常使用与任何系统无异。
    \begin{itemize}
        \item 有文件资源管理器（GNOME的Nautilus、KDE的Dolphin）。
        \item 有图形化的软件商店，软件的安装与更新同样可以点几下鼠标完成。
        \item 命令行只是它更强大的一面，但绝不是全部。
    \end{itemize}
    在下面这些领域，Linux要么有开源替代，要么有成熟的商业支持。
\end{frame}

\begin{frame}
    \frametitle{文档与表格}
    图形化编辑文档本身，其实就是一件糟糕的事
    \begin{itemize}
        \item Word → 用Markdown或LaTeX写作，内容与格式分离，纯文本便于版本管理。
        \item PowerPoint → Markdown有Marp，LaTeX有Beamer，幻灯片本质上只是一种特殊的文档。
        \item Excel → 数据本质上是表格，用\code{.csv}存储，用\code{pandas}等Python库处理。
        \item 如果仍需要传统Office，开源的有LibreOffice，商业的有WPS。
        \item PDF阅读器系统自带。
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{网络与通信}
    \begin{itemize}
        \item 浏览器：Firefox
        \item 邮件客户端：Thunderbird
        \item 密码管理器：pass、KeePassXC
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{图形与图像}
    \begin{itemize}
        \item 矢量绘图：Inkscape
        \item 位图处理：GIMP
        \item 照片管理：DigiKam、RawTherapee
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{开发工具}
    \begin{itemize}
        \item C/C++：\code{gcc}、\code{g++}、\code{make}。ARM开发也不必依赖Keil，\code{gcc-arm-none-eabi}即可，Keil更多是习惯而非必需。
        \item Python：系统自带\code{python}，配合\code{conda}、\code{uv}管理环境。
        \item 代码编辑器：VSCode同样可用，VSCodium则是去除遥测的版本。
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{工程软件}
    \begin{itemize}
        \item 电路板设计：KiCad
        \item 机械加工：FreeCAD
        \item FPGA：Vivado提供Linux版，纯仿真可用Verilator与GTKWave。
        \item 数值计算：Mathematica、MATLAB均有Linux版，开源有Octave。
    \end{itemize}
\end{frame}

\begin{frame}

\subsection{如何开始？}

\begin{frame}
    \frametitle{开始使用Linux}
    即使完全不熟悉Linux也没有关系，有两种平滑的入门方式
    \begin{itemize}
        \item \textbf{WSL}（Windows Subsystem for Linux）：在Windows中直接运行一个真实的Linux子系统，适合先熟悉命令行与开发环境。
        \item \textbf{双系统}：为Linux划分一块磁盘空间，开机时选择进入哪个系统，适合希望完整体验Linux的用户。
    \end{itemize}
    无论哪种方式，都请使用\textbf{Ubuntu 24.04}或\textbf{Ubuntu 26.04}。
\end{frame}

\begin{frame}
    \frametitle{双系统：准备工作}
    \begin{itemize}
        \item 下载Ubuntu 24.04或26.04的系统镜像（ISO）。
        \item 使用BalenaEtcher或Rufus将镜像写入U盘，制作启动盘。
        \item 若Windows启用了BitLocker，\textbf{请务必先关闭，否则可能导致Windows损坏}。
        \item 在Windows的磁盘管理中压缩卷，留出未分配空间用于安装Ubuntu。
    \end{itemize}
\end{frame}

\begin{frame}
    \frametitle{双系统：分区与安装}
    \begin{itemize}
        \item 将启动盘插入电脑，重启，按F2、F10或DEL进入BIOS，选择从U盘启动。
        \item 在图形界面中完成安装，注意选择中文语言和第三方驱动。
        \item 在分区配置中选择手动分区，在未分配空间上创建分区并挂载至\code{/}，文件系统推荐Btrfs而非默认的Ext4。
    \end{itemize}
    \textbf{创建分区会格式化对应区域，请务必不要格式化Windows正在使用的分区！}
\end{frame}
